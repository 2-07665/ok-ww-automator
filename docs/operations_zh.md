# 运行任务

## 调度与账号

使用共享 Python 3.12 环境执行 `python -m ok_ww_automator.scheduler --mode MODE`。模式为 `daily`、`stamina`、`weekly`、`stamina-weekly`。未指定 `--account` 时执行所有发现的账号；重复指定可选择账号及顺序。账号按顺序执行，并用独立进程隔离上游全局状态。

默认更新流程 fetch OK-WW，以 `--ff-only` 合并 `origin/master`，再将 `requirements.txt` 安装到当前 Python。历史分叉或本地改动冲突会让更新失败。`--skip-update` 跳过更新；`--ww-root`、`--ww-remote`、`--ww-branch` 可指定其他仓库和分支。此步骤不更新 Automator，也不更新同级 ok-script 源码仓库。

在 Windows 任务计划程序导入相应 `windows/*_task.xml`，修改 Python 路径、工作目录、登录用户、最高权限和触发时刻。周常及组合模板默认禁用，需要手动启用。体力和体力+周常模板选择一个，不要重复触发。

Windows 触发时刻使用系统本地时间；体力预测的 `DAILY_HOUR`/`DAILY_MINUTE` 使用北京时间 UTC+8。周常规则和周常报告使用配置的服务器时间，日常/体力报告使用系统本地时间。这些 env 设置不会创建 Windows 触发器。执行时保持游戏桌面可访问。

## 日常与体力

日常任务读取表格，按需消耗“跳过一次”标记，可选地通过 Waves API 签到，然后执行上游 DailyTask。完成后读取游戏体力和活跃度，写日志并发送通知。已结束的战令属于可选内容；其他任务错误仍保留。

游戏内读取的活跃度达到 100 且没有任务错误时，日常记为成功。100 是完成门槛，活跃度可以超过 100（如 130、140），报告保留实际读数。读数缺失、不足 100 或存在任务错误时，需要复查。

体力任务先请求 Waves API，失败或未启用时单独启动游戏进行 OCR。根据距离下次日常的时间预测恢复量，不需要消耗时跳过刷取。当前预测假设普通/备用体力上限为 240/480，普通体力每六分钟恢复一点，满后备用每十二分钟一点；无音区每次 60，凝素/模拟领域每次 40。预测不是消费保证，实际刷取量由上游任务决定。

Config 读取失败时，当前行为是使用默认配置，并把读取错误记入决策说明。默认启用日常/体力、选择无音区 #1、关闭关机；缺失凭据仍会阻止 Sheets 客户端初始化。日志写入或通知发送失败会尽可能记录，远端日志不可用时请查看本地输出。

最终状态包括 `success`、`skipped`、`needs review`、`failure`。Healthchecks 将 success/skipped 视为正常，needs-review/failure 视为失败。Mailgun/WxPusher 接收最终报告，`NOTICE_SKIP_SUCCESS` 仅抑制成功报告。凭据和通知配置见[配置说明](config_zh.md)。

每次尝试使用独立游戏子进程，包含启动及退出的总时限为：日常 40 分钟、体力刷取 20 分钟、体力读取 15 分钟；任务执行本身的限制为日常 30 分钟、体力 10 分钟。运行器通过 `RETRY_MAX_ATTEMPTS` 和 `RETRY_DELAY_SECONDS` 控制重试。

游戏尝试在启动前和结束后关闭已知鸣潮进程，并覆盖上游 **Exit After Task** 设置，避免最终 OCR 前退出。是否关机由表格设置决定，跳过或失败后也会遵守。多账号关机统一推迟到所有选中任务完成后，任一账号请求即可触发最终关机。

## 周常乐园

周常不使用 Sheets、Waves API、Mailgun 或 Healthchecks。在各账号 env 中设置：

```dotenv
GAME_SERVER=CN
WEEKLY_RUN_DAYS=1,3,5
WEEKLY_NOTICE_DAY=5
NOTICE_ENABLED=true
NOTICE_CHANNEL=wxpusher
WXPUSHER_SPT=...
```

服务器使用固定时差，不随夏令时变化：`CN`/`ASIA`/`SEA`/`HMT` 为 UTC+8，`US` 为 UTC−5，`EU` 为 UTC+1。因此美服重置时刻为周一 09:00 UTC，即 05:00 EDT 或 04:00 EST。未设置或无效的 `GAME_SERVER` 会阻止周常执行；文件名及通知标签不决定服务器。

通知阈值是服务器通知日的 00:00，周一则取新周开始的 04:00，实际通知仍需调度触发。例如 `WEEKLY_NOTICE_DAY=6` 且每天 17:00 EDT 执行时，未完成的国服周常可在周五通知，美服则在周六通知。此设置不改变 Windows 触发器或日常/体力的北京时间预测目标。

星期值为 1=周一至 7=周日，执行日留空表示每天。周次按所配置服务器时间周一 04:00 重置。执行日按服务器自然日计算，因此周一 04:00 前的调用仍属于上一周。定时调用只在允许日执行，本周已成功则直接跳过，包括更新。上游无错误结束，或当前 Garden 任务产生精确完成消息，均可记为成功。最多尝试两次，同时受重试配置及每次调用共用的 40 分钟预算约束；预算包括更新、游戏运行和重试等待，强制清理与通知可能额外耗时。

通知日及之后，本周仍未完成时发送 WxPusher 失败通知。允许执行日先尝试任务；非执行日也可通知。成功送达每周只记录一次，失败可在后续调用重试。通知必须有调度调用才会发生，应在通知日或之后至少安排一次触发。已记录但未完成的周次可在重置后补报，从未调用的周次没有记录。

本地状态保存在 `.state/weekly/`，按 env 绝对路径区分。记录以服务器和 UTC 重置时刻标识周次，并保存 UTC 成功完成时间。本次更新不迁移旧版数据库，升级时需清除旧周常状态。重命名配置或删除状态会丢失去重信息。同一账号已有周常锁时，并发请求跳过。

`--mode weekly --run-now`（启动器单独“周常乐园”也使用此模式）忽略执行日和本周成功记录。手动成功会更新记录，手动失败不覆盖此前成功。单独周常不请求电脑关机。

`--mode stamina-weekly` 先完成所有账号的体力、日志、通知和 Healthchecks，再执行允许日且本周未完成的周常，最后遵守体力任务的关机请求。一个体力账号失败不会阻止后续任务，更新只在体力开始前执行一次。组合模板没有 Windows 两小时截止限制，请避免调度重叠。

## 启动器与额外任务

从 [Releases](https://github.com/2-07665/ok-ww-automator/releases) 下载启动器，放入 Automator 根目录或 `dist/`，保留共享 `.venv` 和 OK-WW 仓库。运行时请求管理员权限。同一时间只执行一个受管理操作，**停止**会终止其进程树；完整输出保存到 `logs/launcher-*.log`。

**启动所选游戏**要求恰好选择一个账号，读取其游戏路径直接启动，按钮有三秒冷却。它独立于调度操作，不关闭已有游戏，也不跟踪或停止这个直接启动的游戏。

**OK GUI**执行 `ok_ww_automator.ok_main`，在内存中加入三个任务，不修改上游源码：

| 任务 | 前置条件与行为 |
| --- | --- |
| 固定位置声骸速刷 | 将单人卡提希娅放到预定固定 Boss 位置。记录完成的战斗次数，速度包含等待和拾取；检测不到 Boss 超时会报错停止。 |
| 数据坞五合一 | 中文游戏界面，融合未锁定声骸。提交前导航失败可重试，提交后的结果无法确认则停止；重启前检查背包。 |
| Echo OCR | 中文声骸装备/强化页面。默认定期向 UDP `127.0.0.1:9999` 发送有效副词条，间隔和端口可在任务设置中调整；无效识别保留接收端上次结果。 |

**自动速刷**使用当前已打开的游戏和同一固定位置任务。结束时间为系统本地 `HH:MM`，已经过去的时间按次日计算。到点停止刷取并在五秒后关机；任务出错则停止，不发起关机。统计显示在本地，这些自定义任务目前不会向旧的 `5to1` 工作表追加数据。

构建、发布和上游兼容性诊断见[维护指南](maintenance.md)。
